# 迁移与恢复环境

## 整个工作区换文件夹或盘符

关闭 Boyo，将照片拍摄组、`已删除备份` 与整个工具目录一起移动，保留它们的相对位置，再双击新位置的 `启动Boyo.cmd`。

源码目录与运行数据目录 `local` 保持同级：

```text
Boyo/
  repo/           源码目录，名称可自定义
  local/          运行环境与数据
```

`local` 携带独立 Python、已安装依赖、设置、数据库、图集、学习记录和恢复日志。首次从新位置启动会离线修复虚拟环境和命令入口，再用少量照片内容检查识别原工作区；后续普通启动复用结果。

只移动工具而不移动照片时，程序继续使用设置中原来的照片路径。

## 改变目录层级后修复

自动识别依赖已登记照片仍保持相对位置。如果照片工作区与工具的相对位置改变，在新的源码目录打开 PowerShell，运行：

```powershell
..\local\python\python.exe .\portable_env.py --workspace 'E:\照片工作区'
```

把示例路径换成实际工作区。命令修复路径和状态关联，照片保留在原位置。目标照片的路径与内容对应时才沿用原状态；改变内容的文件会按既有规则使旧缓存或标签失效。

也可以运行源码目录中的 `repair.cmd`，传入同样的 `--workspace` 参数。

## 换电脑或环境损坏

同架构的 Windows x64 电脑可以携带整个工具目录迁移。缺少系统运行组件、环境未复制完整或改变 Python 版本时，先在新电脑安装 Python，再在源码目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\安装环境.ps1
```

该脚本可能联网补齐依赖。重新安装环境时保留 `local/settings`、`local/data` 和 `local/models`；恢复文件还需要相应的照片备份目录。

## 应保留的数据

| 路径 | 内容 |
| --- | --- |
| `local/settings/` | 工作区绑定和设置 |
| `local/data/` | 留删、图集、关联与文件恢复记录 |
| `local/models/` | 视觉权重和个人模型 |
| 工作区的 `已删除备份/` | 已移动的 JPG |
| 各拍摄组的 `deleteraw/` | 已移动的 RAW / XMP |

`local/cache` 可重新生成，但保留能减少再次分析和读取照片。核对新位置的照片、状态、图集与恢复入口后再处理旧副本；两个副本中的状态库各自独立，不自动合并。
